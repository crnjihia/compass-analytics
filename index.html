Engineering Rationale

Architecture Decision Records (ADRs)

Key architectural decisions codified with trade-off analysis and production constraints.

ADR 0001

PostgreSQL Row-Level Security (RLS) for Multi-Tenant Isolation

▼

Context: Shared multi-tenant databases risk cross-tenant data leakage if filtering logic is solely delegated to application code.

Decision: Enforce PostgreSQL engine-level RLS using USING (org_id = current_setting('app.org_id', true)). Automatic Prisma extension wraps every query in a transaction setting SET LOCAL app.org_id.

Status: Approved & Verified (100% test coverage across 7 tenant boundary test suites).

ADR 0002

High-Throughput Go Microservice for Daraja Webhook Ingestion

▼

Context: Safaricom Daraja webhooks can burst to 5,000+ payments/second during peak retail hours. Slow ingestion causes Safaricom to throttle and drop transactions.

Decision: Built a lightweight Go 1.23 microservice using Chi and Redis Streams. Transactions buffer asynchronously in < 2ms and process via consumer group worker pools with atomic deduplication.

Status: Approved & Deployed to GHCR container registry.

ADR 0003

Exact 64-Bit Integer Currency Math (Kenyan Shilling Cents)

▼

Context: IEEE 754 floating-point arithmetic (standard JavaScript number) accumulates subtle rounding errors during tax and multi-item reconciliation.

Decision: Store and compute all monetary values as integer cents (BigInt in JavaScript, BIGINT in PostgreSQL). Formatting routines parse strictly at the presentation layer.

Status: Approved & Implemented in @compass/shared.

ADR 0004

SingleFlight Concurrency Coalescing & Redis Tiered Caching

▼

Context: Dashboard refreshes during traffic bursts can cause cache stampedes that overwhelm PostgreSQL connection pools.

Decision: Implemented in-memory SingleFlight promise coalescing alongside Redis tiered caching with $O(1)$ tenant-wide invalidation via atomic version counters.

Status: Approved (Empirical 99.2% query reduction validated under 20 concurrent identical requests).

ADR 0005

Server-Sent Events (SSE) with Graceful Polling Fallback

▼

Context: Store managers need instant visibility into incoming payments without maintaining heavy full-duplex WebSocket connections across mobile networks.

Decision: Lightweight unidirectional Server-Sent Events connected to Redis Pub/Sub, delivering 15s heartbeats and automatic 5s polling fallback when connection drops.

Status: Approved & Integrated with Next.js App Router.

ADR 0006

AWS Cape Town (af-south-1) Infrastructure & EKS 1.30

▼

Context: Safaricom Daraja gateways in Nairobi experience high roundtrip latency when communicating with European or US cloud regions.

Decision: Deployed entire infrastructure into AWS Cape Town (af-south-1) using Terraform (Multi-AZ VPC, RDS PostgreSQL 16, ElastiCache Redis 7, EKS 1.30).

Status: Approved with verified Terraform configurations.
